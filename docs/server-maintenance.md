# Обслуживание сервера панели

Этот текст для того, кто отвечает за сервер панели, но не пишет код. Здесь написано, что обновляется кнопкой, что обновляется только в плановое окно, какие порты открыты и как безопасно запустить обновление.

## 1. Что обновляет кнопка

В карточке **Panel host (this server)** есть два способа обновления:

- **Components** обновляет **Traefik** (веб-сервер, через который идёт весь HTTPS-трафик) и **Redis** (кэш панели). Во время замены Traefik на несколько секунд недоступны все сайты и админка. Во время замены Redis он на несколько секунд недоступен.
- В том же окне **Components** у строки **Docker** есть своя кнопка **Upgrade to <версия>**. Она обновляет Docker Engine; подробности ниже.
- **Web Server Update** обновляет саму **панель**.

### Обновление Docker из панели

При обновлении Docker перезапускается его демон, а вместе с ним все контейнеры сервера: сайты и сама панель недоступны минуту-две. Поэтому панель не обновляет Docker сама изнутри своего контейнера. Она записывает скрипт в `/etc/dokploy/host-updates/` и запускает его на сервере как отдельную службу systemd `dokploy-docker-engine-upgrade`. Эта служба работает вне Docker и переживает его перезапуск.

Что делает скрипт:

1. Скачивает новые пакеты Docker и сохраняет текущие для отката в `/var/backups/dokploy`. Если скачать не удалось, сервер не меняется.
2. Ставит новые пакеты. Docker перезапускается.
3. До пяти минут ждёт, пока снова заработают Traefik, панель, Postgres и Redis.
4. Если они не поднялись, сам возвращает прежнюю версию Docker из сохранённых пакетов.

Окно с кнопкой можно не закрывать: пока панель перезапускается, оно ждёт и потом само показывает журнал и итог. Журнал лежит в `/etc/dokploy/host-updates/docker-engine-upgrade.log`, на сервере его видно и через `journalctl -u dokploy-docker-engine-upgrade`.

Кнопка работает на серверах с systemd и apt (Ubuntu, Debian, машина OrbStack на Mac). На других серверах панель покажет причину отказа, и тогда Docker обновляют командой из раздела 2.

## 2. Что обновляется только в плановое окно

Postgres кнопкой не обновляется. Для Docker кнопка есть (см. выше), но простой при обновлении такой же, как при ручном запуске. Поэтому его тоже лучше запускать в тихое время и заранее предупреждать пользователей.

**Docker Engine вручную.** Если кнопка недоступна, Docker обновляют командой на сервере: `DOCKER_ENGINE_UPGRADE=1 bash install-agenthits.sh update`. Эта же команда видна в карточке под строкой Docker.

**Postgres (база панели).** Смена major-версии (например, 17 → 18) требует переноса данных. Это отдельная работа, а не обновление. Поэтому сервер сохраняет текущую major-версию: установщик её не меняет. Сейчас с Postgres ничего делать не нужно. Обновление внутри одной major-версии (например, 18.5 → 18.6) выполняет та же команда обновления. Перед заменой она сохраняет резервную копию базы.

## 3. Порты

Для входа по домену открыт только порт **443** (TCP и UDP): через него работают сайты и панель по HTTPS. UDP нужен для HTTP/3. Порт **80** не открывается никогда. Сертификаты выпускаются и продлеваются только через порт 443 (TLS-challenge).

- **3000** (TCP) — прямой вход в панель. Адрес с этим портом установщик печатает в конце установки.
- **SSH** — вход на сервер.

Если включён UFW (команда `bash install-agenthits.sh harden --ufw`), входящие подключения разрешены только для SSH, 443 и 3000. Правила UFW не закрывают порты, которые публикует Docker, поэтому закрыть их таким правилом нельзя.

## 4. Как безопасно запустить обновление

1. Выберите тихое время. Пока заменяется Traefik, все сайты на сервере недоступны. Пока обновляется панель, недоступна её админка. При обновлении Docker останавливается весь сервер.
2. Проверьте свободное место: `df -h /var`. Резервная копия Postgres и копии пакетов Docker лежат в `/var/backups/dokploy`.
3. Запустите одну команду в папке, где лежит файл установщика `install-agenthits.sh`:

   ```bash
   bash install-agenthits.sh update
   ```

   Если вы не root, скрипт сам перезапустится через sudo и спросит пароль. На Mac команда та же, но без sudo.

   Чтобы вывод сохранился в файл, запустите так:

   ```bash
   bash install-agenthits.sh update 2>&1 | tee update-$(date +%F).log
   ```

4. Смотрите вывод. Что значат строки:

   | Строка | Что значит |
   |---|---|
   | `Pre-download failed: <образ>. Nothing was changed.` | Образ не скачался. Сервер не тронут, команду можно повторить позже. |
   | `Error: ... Nothing was changed.` | Остановка до любых изменений. Текст ошибки говорит, что именно не так. |
   | `Postgres <N> stays. A major upgrade is a separate migration; this update does not change it.` | Major-версия Postgres отличается от закреплённой. Postgres остаётся как есть, копия не делается. Это штатно. |
   | `Postgres backup written to <файл>` | Резервная копия базы сохранена перед заменой Postgres. |
   | `Traefik already runs <образ>` | Traefik уже нужной версии, менять нечего. |
   | `Traefik runs <образ>` | Traefik заменён на новую версию. |
   | `<сервис> runs <образ> (previous image kept: <образ>)` | Сервис заменён. Старый образ записан в скобках, он нужен для ручного отката. |
   | Строка про панель с `already up to date` | Панель уже на нужной версии. |
   | Строка про панель с `updated to` | Панель обновлена сейчас. |
   | `Docker Engine is <версия>` | Docker обновлён и работает. Строка появляется только при `DOCKER_ENGINE_UPGRADE=1`. |
   | `Panel host update finished.` | Обновление завершено без ошибок. |

5. Проверьте результат:

   ```bash
   docker service ls
   ```

   У `dokploy`, `dokploy-postgres` и `dokploy-redis` в колонке REPLICAS должно быть `1/1`. Затем откройте панель в браузере.

6. Если обновление остановилось с ошибкой, не запускайте его снова вслепую. Сначала посмотрите логи (раздел 5).

## 5. Где логи

- Установщик на диск логи не пишет. Вывод виден в терминале, а если вы использовали `tee`, он сохранён в файл.
- Панель: `docker service logs --tail 120 dokploy`
- Postgres: `docker service logs --tail 120 dokploy-postgres`
- Redis: `docker service logs --tail 120 dokploy-redis`
- Traefik: `docker logs --tail 120 dokploy-traefik`
- Резервные копии Postgres: `/var/backups/dokploy/`, файлы вида `postgres-<дата>.sql.gz`. Доступны только root, сами не удаляются.
- Копии пакетов Docker, если обновляли Docker: `/var/backups/dokploy/docker-rollback-<дата>/`.

## 6. Диск: что занимает место и как его освободить

Страница **Monitoring**, карточка **Disk Space**.

- Панель раз в минуту читает, сколько занято на диске, и раз в 5 минут спрашивает у Docker размеры образов, кэша сборки и файлов контейнеров. Раз в час она измеряет тома, логи контейнеров, папку `/etc/dokploy` и файлы подкачки. Если занятое место изменилось больше чем на 0,5% диска (минимум 256 МБ), замер делается сразу, поэтому короткий всплеск тоже попадает в историю.
- График показывает день, 3, 7 или 30 дней. Каждый столбец показывает самый заполненный момент своего интервала.
- Таблица «What takes the space» в сумме даёт ровно занятое место. Строка «System and other» содержит всё, о чём Docker не сообщает: систему, системные логи, служебные файлы Docker.
- Список «What changed the most» называет конкретные образы, тома и контейнеры, которые выросли или уменьшились с начала периода.
- Все числа в десятичных гигабайтах (1 ГБ = 1000 МБ), как у Docker. Команда `df -h` считает в двоичных, поэтому показывает меньше: 52,7 ГБ здесь и 50G там — один и тот же диск.
- История хранится 30 дней в `/etc/dokploy/monitoring/disk-history/`. Действие **Clean Monitoring** удаляет её вместе с остальными данными мониторинга.

Блок **Free up space** в той же карточке:

- удаляет старые образы панели, кроме работающего и предыдущего (он нужен для отката), и показывает их список до удаления;
- по галочке очищает кэш сборки Docker. Это безопасно: ничего не ломается, только следующие сборки приложений идут без кэша и дольше.

Логи контейнеров панель измеряет временным контейнером `busybox`, которому каталог Docker с контейнерами подключён только для чтения. Если образ `busybox` скачать нельзя, логи попадают в строку «System and other».
